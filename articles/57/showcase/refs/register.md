# Pattern references: Incidents and hazards register

Searched on Mobbin on 17 September 2026 before the screen was built. Each row records the pattern, the reference, what was taken and what was deliberately left behind.

| Pattern | Reference | Taken | Rejected |
|---|---|---|---|
| Quick filters above a report list | [incident.io, Incidents with status filter](https://mobbin.com/screens/58cf61e8-ef30-48f7-9e6d-cc3114595778) | A row of named quick filters sitting above the list, each carrying its own count, so the manager can see how much work each state holds before clicking; the primary action stays top right | The engineering severity vocabulary (Major, Fixing, Monitoring). A restaurant list is sorted by what needs a person today, not by an engineering severity ladder |
| Row selection and bulk actions | [incident.io, incident list with bulk actions](https://mobbin.com/screens/1d72b14c-95e4-4d38-affb-039c4dc40139) | Row checkboxes and a select-all control in the header, so a manager can act on several closed reports at once | Bulk "Set severity". Severity is set once, from the outcome, after the welfare check. Making it a bulk action would put the classification back in the wrong hands |
| Filter chips that read as key and value | [Klaviyo, Helpdesk all tickets](https://mobbin.com/screens/91b3f8b8-d5ec-4597-8ac1-8e7af35f123b) | Filter chips written as "Type All", "Status Open", "Area All" so the current filter is readable without opening anything; a saved view named in the bar | Sentiment and channel columns, and the upgrade banner |
| A row that opens a side panel | [Navattic, visitors table with detail drawer](https://mobbin.com/screens/79a31934-4ca2-4700-86a5-c180fa735404) | Selecting a row opens a right-hand panel and keeps the list in view, so the manager keeps their place in the queue | The deprecated-view notice and the properties accordion |
| Register with an expiry or due column | [TheyDo, insights list with side panel](https://mobbin.com/screens/7998a1e2-6955-4b34-811a-f5aac41ba0c1) | A trailing column that states what is owed and when, rather than a generic "updated" timestamp | The scoring column |
