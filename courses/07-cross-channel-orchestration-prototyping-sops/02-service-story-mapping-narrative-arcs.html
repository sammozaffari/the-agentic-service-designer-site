📖 1. Theoretical Grounding & Literature Synthesis

Story is structure, not decoration

Donna Lichaw's The User's Journey (2016) makes the load-bearing claim for this module: products and services that "work" narratively are built on the same structural spine as stories — an expositional setup, rising action through a series of crises, a climax, and a resolution (Ch. 3, Structuring Your Product). The user is the hero; the service is the plot machinery that moves them between states. The practical consequence: a service journey is not an unordered bag of touchpoints. The same touchpoints in a different order produce a different experience, because each beat re-frames the customer's emotional reading of the next.

Pine & Gilmore's The Experience Economy (Ch. 3, Staging Experiences) supplies the staging discipline: theme the experience, harmonize impressions with positive cues, eliminate negative cues, mix in memorabilia, engage the senses. Narrative arc tells you when the climax should land; staging tells you what cues must be present at each beat for the arc to be felt. A collect-and-return service whose climax (the kiosk moment) is staffed by conflicting cues — "ready for collection" vs "we need a paper receipt" — fails on both axes at once.

The narrative arc as an ordered, evidence-gated structure

The craft move of this module is encoding the arc as ordered artifact nodes with an explicit tension value per beat. Order carries the theory: the backbone node sequence is the plot.

Why agentic infrastructure

Two failure modes kill workshop story maps. Drift: beats invented in the room lose their connection to research within days. Sequence decay: sticky notes get photographed once and never re-ordered again, so the arc is never tested as an arc. The toolchain addresses both mechanically: story-mapping fails closed unless a journey-map or insight-set artifact already exists, so the backbone is always derived from evidence-gated research; and every beat node must carry a non-empty beat field plus cited evidence before the Critic will pass it.

💻 3. Schemas & Verified Execution

TypeScript schema (@asd/core)

// kind-schema for "story-map" (closed node fields):
//   action: string REQUIRED   beat: string   tension: number   stage: string   actor: string
// relations: derived-from → journey-map | concept-set | prototype-plan
//            supports     → roadmap | prototype-plan | service-blueprint
//
// kind-schema for "storyboard" (closed node fields):
//   scene: string REQUIRED    action: string   actor: string   touchpoint: string   emotion: string
// relations: derived-from → journey-map | concept-set | persona-set
//            supports     → prototype-plan | test-report | walkthrough-script
export interface StoryMapNodeFields {
  action: string                // REQUIRED — what happens at this beat
  beat?: string                 // setup | confrontation | resolution ... (acceptance: non-empty)
  tension?: number              // arc height; order + tension encode the plot
  stage?: string
  actor?: string
}

📊 4. Case Study Lens: Re-Storying Onboarding at Quill (Article 14)

Synthetic illustration — not a production log. Article 14 (Story Mapping & Narrative Structure: Re-Storying Onboarding at Quill) is an illustrative composite from the course corpus.

Quill's onboarding failed Lichaw's test: the touchpoints were individually fine but ordered as an anticlimax — the payoff screen arrived before the customer had done anything to earn it, and the actual climax (first successful publish) was visually indistinguishable from a settings page. The re-storying moved one beat and re-cued two others; activation rose in the composite account. The transferable mechanic: tension values make the arc arguable. When s2 carries tension: 4 against s1's 1, the claim "the kiosk moment is the climax" becomes a falsifiable design assertion the Critic can interrogate against journey evidence — int-01's forty-minute drive is exactly the kind of citation that keeps the climax honest.

And storyboard-authoring rejects placeholder scenes: the forbid-field-values scene acceptance rule plus the closed schema mean a frame with an empty or boilerplate scene stays draft with the failure listed in check.failures.

Verification checklist

  • Story-map backbone has ≥3 ordered beats, each with non-empty beat and a numeric tension.
  • derived-from reference to the journey-map recorded with provenance.
  • Storyboard has ≥4 frames with concrete scene text.
  • Both artifacts final via critic pass; renders/story-map.<id>.svg exists.

🚀 Key Takeaways

  • ✅ Narrative arc is sequence plus tension — encode it as ordered nodes with numeric tension, not prose.
  • ✅ story-mapping derives from an evidence-gated journey; the input gate forbids evidence-free storytelling.
  • ✅ Storyboards dramatize the beats worth testing; they support prototype-plans and walkthrough-scripts (07.4).
  • ✅ The climax is a design claim — make it falsifiable with cited evidence.
