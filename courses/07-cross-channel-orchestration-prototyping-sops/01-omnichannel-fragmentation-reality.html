1. Theoretical Grounding & Literature Synthesis

The channel–touchpoint–ecosystem hierarchy

In Orchestrating Experiences (2018), Chris Risdon and Patrick Quattlebaum give the most operational vocabulary for cross-channel work (Ch. 5, Channels and Ecosystems). Their hierarchy separates three levels that teams routinely conflate:

  • Channel — a medium through which organization and customer exchange value: mobile app, web, SMS, telephony, retail branch, kiosk, connected hardware.
  • Touchpoint — a discrete interaction with five structural elements: Context (the user's situation), Actor (who is present), Channel (the medium), Action (the behavior), and Artifact/Content (the interface or document exchanged).
  • Ecosystem — the full actor set, including partners and internal systems, that must coordinate for any touchpoint to work.

Fragmentation lives at the touchpoint level but is caused at the ecosystem level. When the kiosk "has never heard of" an order the app confirmed, the failure is not the kiosk UI; it is that no ecosystem actor owns order state across the channel boundary. This is why a channel audit must map who holds what state and what is exchanged at each seam — an ecosystem property — rather than inventorying screens.

Gap-first diagnostics

Risdon & Quattlebaum's Ch. 3 (The Orchestration Canvas) contributes the diagnostic reading we apply to the audit. A completed channel map is scanned for four structural failure modes:

  1. Unsupported phases — customer goals with no assigned organizational response.
  2. Orphaned signals — data the organization captures that triggers no action (the app knows the customer is en route; the store never hears it).
  3. Uncoordinated actions — channels emitting conflicting messages (app says "ready for collection", desk says "we need the paper receipt").
  4. Unowned seams — handoffs between channels with no named owner. This is the most common and the most expensive: the seam is where state dies.

The sense-and-respond loop completes the theory: an orchestrated service behaves like an adaptive organism that senses signals (behavioral events, telemetry, context) and responds with coordinated cross-channel action. Fragmented services sense plenty and respond incoherently, because response ownership was never assigned.

Why agentic infrastructure

The theory is fifty years of consensus — Grönroos on service quality as process, Bitner & Shostack on blueprinting, Risdon & Quattlebaum on orchestration — yet channel audits still rot in workshop posters for three reasons the @asd toolchain removes mechanically:

  • Provenance decay: the claim "the kiosk re-keys 42% of orders" loses its source within a week. In the toolchain every ecosystem node must cite SHA-256-addressed evidence at write time; a dangling reference is never persisted.
  • Ownership without a gate: naming a seam owner in a workshop is a declaration; here the Critic contract for orchestration-canvas is literally "reject any ownership assignment with no stated reason" — the gap-first diagnostic is executable.
  • The canvas is not the artifact: collaborative boards (Figma, Penpot, Pencil, paper) are where humans sketch; the ecosystem-map artifact is where the audited truth lives. sd_canvas_add links the two with the board URL recorded on the project, so the sketch and the audited artifact can never silently diverge in provenance.

2. Agent Topology & Method Contracts

Two methods compose the channel audit. Both are data — manifests in suite/packages/knowledge/data/methods/ — and both route through the Critic gate.

Role Method Contract facts (verified live) Tools exercised
Researcher ecosystem-value-mapping (step 1) Gathers partner/channel capability notes; the method's evidence input gate requires ≥3 evidence records sd_evidence_add, sd_evidence_query
Mapper ecosystem-value-mapping (owner) Produces kind ecosystem-map; acceptance: min-nodes 3, min-evidence-per-node 1, field-non-empty value sd_method_run, sd_artifact_write
Ideator orchestration-canvas (owner) "Propose which actor should own each touchpoint across the ecosystem, and why." Requires an existing ecosystem-map artifact plus ≥1 evidence record sd_method_run, sd_artifact_write
Mapper orchestration-canvas (step 2) "Revise the ecosystem map to show the proposed ownership for every actor." Acceptance adds field-non-empty role sd_artifact_write (update via --artifactId)
Critic both (reviewGate: critic) Gate instruction: "Reject any ownership assignment with no stated reason." Pass requires ≥1 evidence-cited row and zero defects sd_review, sd_review_list
Human designer checkpoints scope-confirmation (before-run) and handoff-approval (before-handoff to Ideator) are human-only decisions sd_phase_advance (with approval receipt)

4. Case Study Lens: Juniper Retail Collect-and-Return (Article 13)

Synthetic illustration — not a production log. Article 13 (Orchestrating Multi-Channel Experiences: One Collect-and-Return Service at Juniper Retail) is an illustrative composite from the course corpus.

The verified session above re-runs Article 13's opening move. The engagement's diagnostic findings map one-to-one onto Risdon & Quattlebaum's four gap classes:

Gap class Juniper finding Evidence record
Unowned seam App→kiosk handoff has no owner; order state re-created tel-01 — 42% channel-switch rate
Uncoordinated actions App promises "ready"; desk demands paper receipt int-01, doc-01
Orphaned signal App knows the customer is en route; store systems never receive it int-01
Unsupported phase Online-initiated returns have no in-store response path int-02, doc-01

The orchestration pass assigns exactly three ownerships — app as state orchestrator, kiosk as token consumer, concession desk as exception fallback — each citing the telemetry or transcript that justifies it. The Critic gate's job is to keep "because it feels right" ownership assignments out of the artifact.

Deliberate fail-closed demo

Run orchestration-canvas on a project with no ecosystem-map. Verified output:

asd method-run: method "orchestration-canvas" requires at least 1 artifact input of
kind ecosystem-map; project has 0. Produce the typed input artifact before starting.

The method catalogue encodes the theory's dependency graph: you cannot assign channel ownership before the channel audit exists.

Verification checklist

  • Ecosystem-map has ≥3 nodes, each citing ≥1 SHA-256 evidence id from evidence/index.json.
  • Every node carries non-empty value (audit) and non-empty role (orchestration pass).
  • Canvas link registered with a valid --tool enum value and an https:// URL.
  • Critic pass verdict recorded; artifact status final.
  • sd_factcheck exits 0.

Key Takeaways

  • Fragmentation is an ecosystem property: state dies at unowned seams, not in bad screens.
  • The channel audit is an ecosystem-map (value exchange + role per actor), gated by evidence and the Critic.
  • orchestration-canvas fails closed until the audit map exists — the toolchain enforces diagnostic order.
  • Collaborative boards are linked (sd_canvas_add), never confused with the evidence-gated artifact.
