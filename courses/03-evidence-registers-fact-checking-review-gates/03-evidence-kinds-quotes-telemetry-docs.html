1. Theoretical Grounding & Literature Synthesis

Triangulation is the method, not a nice-to-have

This is Service Design Doing (ch. 04 "Research Methods") states the rule directly: relying on a single data source introduces distortion, so valid research combines direct observation (what people do), contextual inquiry / interviews (how people explain why), and secondary/quantitative data (how often the pattern occurs at system scale). Kalbach (Mapping Experiences, ch. 03) adds the granularity requirement: a complete map needs actions, thoughts, and feelings at every journey phase — and no single instrument captures all three.

The @asd evidence taxonomy is that triangulation discipline, closed and enforced:

Kind Epistemic role Kalbach's strand Failure mode when used alone
quote Verbatim voice — thoughts and feelings in the speaker's own words thoughts, feelings Anecdote: vivid but unscaled ("one angry caller")
telemetry Operational magnitude — how often, how long, how many actions (at scale) Soulless aggregate: real but unexplained ("47% abandonment" — of what feeling?)
document Institutional truth — policy, SLA, regulation the service is obliged to honor context / constraints Aspirational fiction: what the org says happens

A claim corroborated by all three — a caller's verbatim fury, the IVR abandonment curve, and the charter clause being violated — is what the literature calls a research-based finding. Anything less is a hypothesis wearing a finding's clothes.

Why observation is not a kind

A tempting fourth category — "the designer observed that…" — is deliberately absent. The kind set is closed at the schema level:

$CLI evidence-add --projectId $PID --source obs-01 --kind observation --body "Operator seemed stressed"
asd evidence-add: invalid arguments: "arguments.kind" must be one of ["quote","telemetry","document"]   (exit 1)

The design rationale: an observation is an interpretation wearing a quote's authority. If the operator said something, capture the quote verbatim. If the system logged something, capture the telemetry row. If a rule exists, capture the document clause. What the designer inferred belongs downstream — in an artifact node's fields, where acceptance rules and the critic gate can interrogate it — never in the evidence register, where records are supposed to be pre-interpretive ground truth. This is Kalbach's assumption-versus-research line (ch. 03) enforced as a type error.

3. Production Schemas, Code & Verified Execution

The import contract (@asd/core)

export type ImportErrorPolicy = 'fail' | 'skip'
export type ImportLocalEvidenceInput = {
  readonly projectId: string
  /** A local file or directory only; URL schemes are rejected. */
  readonly path: string
  /** Human-supplied source label retained on every imported record. */
  readonly source: string
  readonly encoding?: 'utf8' | 'utf-8'   // strict UTF-8 only; latin1 etc. rejected
  /** Maximum size per file, in bytes. Defaults to 5 MiB. Hard cap — never truncates. */
  readonly maxBytes?: number
  readonly onError?: ImportErrorPolicy   // default 'fail'
}

Telemetry, added live

$CLI evidence-add --projectId $PID --source tele-ivr --kind telemetry \
  --body "avg_hold_seconds=2418; abandonment_rate=0.47; window=2026-08-01..2026-08-21; calls=11840"

{ "evidence": {
    "id": "ee12720dce747fdbac83f3916a85e06d418fe2ded1100eab72331ab83247fc42",
    "source": "tele-ivr", "kind": "telemetry",
    "body": "avg_hold_seconds=2418; abandonment_rate=0.47; window=2026-08-01..2026-08-21; calls=11840",
    "capturedAt": "2026-08-22T11:35:06.900Z" } }

Note the authoring discipline: the body carries its window and n so a critic can judge whether the magnitude claim is current and sufficiently sampled. Telemetry without a window is a number without a question.

Each JSON array element became one document record with full provenance — ordinal lets you cite which clause. Now the flag probes, all real outputs:

# path — must live inside the workspace (containment probe)
$CLI evidence-import --projectId $PID --path /tmp/asd-c03-docs/repair-charter.md --source charter-2026
asd evidence-import: evidence import path must be inside the ASD workspace root   (exit 1)

# maxBytes — a HARD CAP, not truncation
$CLI evidence-import … --maxBytes 80
asd evidence-import: evidence import failed for …/repair-charter.md: file size 270 exceeds maxBytes 80   (exit 1)

# encoding — strict UTF-8 only; latin1 is rejected as an argument
$CLI evidence-import … --encoding latin1
asd evidence-import: invalid arguments: "arguments.encoding" must be one of ["utf8","utf-8"]   (exit 1)

# onError fail (default) — one undecodable file aborts the import
asd evidence-import: evidence import failed for …/bad-encoding.txt: The encoded data was not valid for encoding utf-8   (exit 1)

# onError skip — the bad file is reported, the run succeeds
$CLI evidence-import … --onError skip
{ "imported": [], "skipped": [ { "path": "…/bad-encoding.txt",
    "error": "The encoded data was not valid for encoding utf-8" } ], "files": 0, "bytes": 0 }   (exit 0)

And the two content probes worth internalizing: importing a directory walks it recursively (a two-file bundle produced two records, "files": 2), and re-importing it returned the same ids — content addressing makes bulk import idempotent. A .pdf fails as unsupported evidence file type ".pdf": the importer is loss-minimising by design and will not OCR or infer content.

Import record flow — sequence view

Worked example: a poisoned CSV row fails closed

The librarian stages a three-row callback log and imports it. One row is malformed; the exercise is to watch exactly what the pipeline refuses to do.

Fixture — imports/callbacks.csv (staged inside the workspace).

date,caller,note
2026-08-18,c-11,"Prescription was ready but nobody called."
2026-08-19,c-12,"They said the portal would show the result — it never did.
2026-08-20,c-13,"Callback came two days late."

Row 2 opens a quoted field and never closes it.

Step 1 — default policy (onError: fail).

asd evidence-import: evidence import failed for …/imports/callbacks.csv:
  CSV record contains an unclosed quoted field   (exit 1)

Nothing is imported. Fail-closed is file-level: one poisoned row blocks the whole file, because importing rows 1 and 3 while dropping row 2 would fabricate a cleaner dataset than reality provided.

Step 2 — --onError skip.

{ "imported": [],
  "skipped": [ { "path": "…/imports/callbacks.csv",
                 "error": "CSV record contains an unclosed quoted field" } ],
  "files": 0, "bytes": 0 }

Exit 0, with the failure named in the report — skip means "quarantine and disclose," never "absorb silently."

Step 3 — repair row 2 (close the quote) and re-import.

{ "imported": [
    { "id": "a1f0…",  "kind": "quote", "body": "date,caller,note",
      "origin": { "relativePath": "callbacks.csv", "format": "csv",
                  "encoding": "utf8", "bytes": 208, "record": "row", "ordinal": 1 } },
    { "id": "7c3e…",  "kind": "quote", "body": "2026-08-18,c-11,\"Prescription was ready but nobody called.\"",
      "origin": { "record": "row", "ordinal": 2, "…": "…" } },
    { "id": "e59b…",  "kind": "quote", "body": "2026-08-19,c-12,\"They said the portal … never did.\"",
      "origin": { "record": "row", "ordinal": 3, "…": "…" } },
    { "id": "b27d…",  "kind": "quote", "body": "2026-08-20,c-13,\"Callback came two days late.\"",
      "origin": { "record": "row", "ordinal": 4, "…": "…" } } ],
  "skipped": [], "files": 1, "bytes": 208 }

Expected artifact. Four quote records in the register (CSV rows import as quote), each carrying full provenance — relativePath, format: "csv", bytes, record: "row", ordinal — and each id being sha256([source, "quote", body, origin]).

Interpretation. Three habits fall out of the run. First, the importer is a record splitter, not a parser: it stores the raw row text and never invents cell content, which is why the header row imports as ordinal 1 — cite data rows as ordinals 2–4. Second, provenance columns make a citation answer "which row of which file" exactly, so a critic can check 7c3e… against the physical log. Third, because ids are content-addressed, the repair re-import converges — fixed rows mint ids once, and no duplicate records appear no matter how many times the corrected file is re-imported.

4. Case Study Lens: Article 09 — Journey Mapping from Transcripts (Albatross Airways)

Synthetic illustration — not a production log. Article 09 is a fictional aviation disruption-recovery composite; this lens applies the taxonomy to its narrative.

Article 09 is the taxonomy's natural habitat: an irregular-operations case where passengers' verbatim fury ("first apology to rebooked seat") had to be fused with operational telemetry (delay minutes, rebooking queues) and institutional documents (compensation policy). The article's method sources — Kalbach ch. 04 among them — are the same ones stamped on the journey-from-transcripts contract you ran in 03.1. The triangulation test from §1 is the article's implicit quality bar: a journey stage backed only by a quote is an anecdote; backed only by delay statistics is a spreadsheet; backed only by policy is fiction. The recovery map became trustworthy where all three strands crossed — and the register's closed kind set is what kept "the ops lead thinks passengers felt calm" out of the evidence base and in the artifact's contested fields where the critic could veto it.

# D. Fail-closed probes: import a path OUTSIDE the workspace (exit 1);

Verification checklist

  • observation was rejected with the exact enum error.
  • Your telemetry id matches the lesson's (same content → same id).
  • The JSON import produced kind: "document" records with origin.record: "json-value" and ordinals.
  • onError: skip yielded exit 0 with a non-empty skipped[]; default behavior yielded exit 1.
  • You can state, unprompted, why maxBytes is a hard cap rather than truncation (a truncated quote is a falsified quote).

Key Takeaways

  • The kind set is closed and schema-enforced: quote | telemetry | document; observation fails with a real argument error, because inference belongs in artifact fields, not in ground truth.
  • Triangulation maps to kinds: quote = voice, telemetry = magnitude, document = institutional constraint; findings need all three legs.
  • The importer is conservative by construction: workspace containment, five extension allowlist, strict UTF-8, hard byte caps, symlink refusal, fail|skip error policy.
  • Imported records carry ordinal provenance, and re-import is idempotent via content addressing.
