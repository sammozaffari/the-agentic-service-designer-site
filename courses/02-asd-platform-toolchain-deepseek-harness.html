Course 02: The ASD Platform & Toolchain

The @asd Runtime Engine, the MCP Server, and CLI Ergonomics

Deep-dive technical breakdown of the ASD runtime stack. Teaches the @asd package architecture (core schemas, engine execution, knowledge registry, render compilation), drives the same 29-tool surface over both the stdio MCP server (29 tools, 216 repo-corpus resources, 10 role prompts) and the standalone CLI, and covers deterministic SVG/HTML export into project renders/. DeepSeek Harness (dsh) is introduced honestly as a deferred integration surface with separate acceptance evidence.

Paradigm Shift 01 / 10

One Engine, Every Surface

  • The @asd monorepo compiles one canonical engine to two student surfaces: the asd CLI and the MCP stdio server.
  • 29 tools with identical acceptance rules and identical fail-closed behavior — zero platform divergence.
  • Host packs (claude-code, codex, kimi, opencode) vendor the same server and add role prompts in host format.
  • You learn the engine once; every host, terminal, and GUI speaks the same contract.
@asd/core (schemas)→ @asd/engine (30 tools)→ @asd/render (SVG)→ @asd/runtime (CLI · MCP stdio)
"One engine, one contract — the same practice wherever a designer actually works."
The Executable Spine 02 / 10

One Canonical Loop Behind All 8 Courses

  • Every module runs the same verified loop: project → evidence → method contract → artifact draft → critic gate → factcheck → export → human-gated phase advance.
  • The CLI and the MCP server execute the identical loop against the identical workspace store.
  • sd_method_run fails closed below the method's evidence minimum — no evidence, no artifact.
  • sd_phase_advance refuses to run without a human approval receipt JSON.
sd_project_create→ sd_evidence_add→ sd_method_run→ sd_artifact_write→ sd_review→ sd_factcheck→ sd_export_report→ sd_phase_advance
"Agents prepare and verify with receipts; human leaders decide with accountability."

Module 02.4 06 / 10

Terminal Ergonomics with the asd CLI & Headless Scripting

  • CLI grammar: asd <kebab-short-name> --flag value — project-create, evidence-add, method-run, review, factcheck, phase-advance.
  • There is no asd init, run, status, agent, or render; the 29 short names are the whole grammar.
  • Evidence ids are 64-hex SHA-256 over [source, kind, body, origin] — content-addressed and deduplicating.
  • Headless by design: every lecture runlog in this curriculum is a paste-able CLI session with exit-code semantics.
asd <verb> --flags→ ASD_WORKSPACE JSON store→ Receipts & runlogs→ exit 0 / fail-closed exit 1
"Twenty-nine verbs is the whole grammar; memorize the loop, not the manual."
Module 02.5 07 / 10

Deterministic Visualization: Compiling Structured JSON to Flawless SVG/HTML

  • LLMs should never draw: typed JSON compiles to zero-hallucination visuals.
  • sd_export_artifact renders e.g. renders/journey-map.<id>.svg — deterministic @asd/render output.
  • sd_export_report --kind artifact-dossier renders the full HTML dossier.
  • Deterministic means diff-stable: same artifact, same bytes, every run.
Typed artifact JSON→ @asd/render compiler→ SVG per artifact→ HTML artifact-dossier
"A renderer that cannot hallucinate is a renderer you can ship."

Dogfooding the Runtime 09 / 10

The Verified Toolchain Behind This Course

  • Introspection: sd_knowledge, sd_schema_get --kind <kind>, sd_template_list/get, sd_practice_get.
