1. The Sprint as Theory, Compressed

Kumar's 101 Design Methods (books/17-101-design-methods/01-innovation-as-a-process.md) frames innovation as Knowing → Making against Reality → Abstraction. This sprint traverses three quadrants in one loop: Reality/Knowing (verbatim capture), Abstraction/Knowing (journey synthesis from transcripts), and the governance membrane between Knowing and Making (critic gate + human phase advance). TISDD's research standards (Ch. 4: triangulation across say/do/observe) are satisfied structurally: you will capture all three evidence kinds before the method will even run.

2. The Verified Run, End to End

Setup (from the repo root; the CLI is the built runtime):

export ASD_WORKSPACE=/tmp/asd-sprint-$(date +%s)
CLI="node suite/packages/runtime/lib/cli.mjs"

$CLI project-create --name "Fernwood Repairs Sprint" --client "Fernwood Council" \

$CLI evidence-add --projectId <pid> --source int-03 --kind observation --body "Advisers seem rushed."

Step 3 — Contract (mapper reads before writing)

$CLI method-run --projectId fernwood-repairs-sprint-f0d60fa1 --methodId journey-from-transcripts

Contract highlights (full JSON in module 01.1): owner:"mapper", reviewGate:"critic", acceptance min-nodes:3, min-evidence-per-node:1, field-non-empty on emotion and touchpoint, inputs:[{kind:"evidence-set",min:3}], availableEvidence:4.

Fail-closed demo B — insufficient evidence. In a second project with only 2 records, the same command exits 1:

asd method-run: method "journey-from-transcripts" requires at least 3 evidence records; project has 2. Capture evidence with sd_evidence_add first.

Step 4 — Draft artifact (mapper writes; edges need id, from, to, relation, fields)

Fail-closed demo C — dangling citation (expect exit 1):

$CLI artifact-write --projectId <pid> --methodId journey-from-transcripts --title "t" \
  --nodes '[{"id":"n1","label":"Report damp","evidence":[{"evidenceId":"deadbeef…(64 hex)"}],"fields":{"emotion":"x","touchpoint":"portal"}}]'
# → asd artifact-write: node "n1" cites evidence "deadbeef…" which is not in the project evidence store

Step 5 — Critic gate: veto first, then pass

$CLI review --projectId fernwood-repairs-sprint-f0d60fa1 --artifactId 2baab028b1fb4cc997d5f8d977a049f5 \

    "message":"Stage s2 emotion is telemetry-adjacent; attach the interview quote that names the feeling.",
    "fix":"Add int-01 quote about feeling ignored to s2 evidence array.",
    "evidenceId":"81f9693424964b641264136fc2e9741a4b250c9f4b9861cbd98b7f2a0ed05b80"}]'

{"status":"draft","verdict":"veto","logArtifactId":"de73bd97b3dc4ee0bfc29f4087049e7d","rowsWritten":1}

$CLI review --projectId fernwood-repairs-sprint-f0d60fa1 --artifactId 2baab028b1fb4cc997d5f8d977a049f5 \

5. Capstone Checklist (this IS the lab)

The full scripted version lives in courses/labs/lab-01-fundamentals/ with a verifier. Working through §2 above, confirm:

  • Project created in discover; you can explain the difference between this and a method phase.
  • Four evidence records minted across all three kinds; observation rejected (demo A).
  • Contract read; availableEvidence matched your count; the 2-record project refused to run (demo B).
  • Dangling evidenceId refused at write (demo C); valid write returned accepted:true, status:"draft".
  • Veto produced a review-veto-log artifact; pass flipped status to final.
  • factcheck exited 0 with integrity.dangling: [].
  • Both renders exist under <project>/renders/.
  • Phase advance refused without receipt, then recorded a phase-gate-decision with factcheckPass:true.
  • You ran everything in a disposable ASD_WORKSPACE and can delete it without losing anything.

Key Takeaways

  • The loop is short enough to memorize and strict enough to trust: 8 commands, 3 fail-closed refusals, 1 human signature.
  • Every refusal is a feature. Invalid kinds, thin evidence, dangling citations, unsigned phases — each exit 1 is a workshop-theater failure mode made impossible.
  • Receipts are the deliverable. The phase-gate decision binds who approved to the exact state of the evidence at approval time.
  • You are ready for Course 02 when you can run this sprint from memory and explain each gate to a skeptic.
