Module 02.5: The Deterministic Export Pipeline — Typed JSON to SVG and HTML, Byte for Byte

Course: The ASD Platform, Toolchain & DeepSeek Harness (dsh) · Level: Foundation · Duration: 55 min · Format: Theory, Verified Export Runlog & Hands-on Lab

Learning Objectives

By completing this module, you will be able to:

  1. Argue the determinism thesis: why LLMs must never draw diagrams directly, and what a compiler gives you that a generator cannot.
  2. Operate both export tools: sd_export_report (six HTML report kinds) and sd_export_artifact (per-kind SVG), with real output paths and byte counts.
  3. Explain where determinism lives: @asd/render's 32 per-kind compilers and @asd/report's section composers — pure functions of the artifact JSON.
  4. Verify determinism yourself: re-export and compare hashes; know which fields (timestamps) are injected and how generatedAt is controlled.
  5. Complete the hands-on lab: export, hash, re-export, compare.

1. Foundational Theory & Literature Grounding

Maps are arguments, and arguments must be reproducible

Kalbach's Mapping Experiences (books/09-mapping-experiences/07-designing-the-map) treats a map as a model — a simplified, defensible claim about reality whose value lies in the integrity of the mapping from observation to representation. If the same evidence produced a different map every time you drew it, the map would stop being evidence of anything. That is precisely the failure mode of asking a generative model to draw: the visual becomes a new, unauditable interpretation layered on top of the data.

Orchestrating Experiences (books/08-orchestrating-experiences/01-why-orchestration) adds the channel dimension: the same underlying model must be renderable as a workshop printout, a stakeholder HTML dossier, and an SVG in a slide deck without semantic drift. Compilation — not regeneration — is what keeps the channels coherent.

The platform's answer: artifacts are the single source of truth (typed, schema-validated JSON); renders are pure functions of artifacts. @asd/render ships one compiler per registered artifact kind (journey-map, service-blueprint, kpi-tree, … 32 kinds), and @asd/report composes fixed document sections (cover, evidence base, traceability matrix, …) around the same JSON. No pixels are invented at export time.

Key principles

  • No hallucination surface: the renderer cannot invent a stage, an emotion, or a quote — it only lays out what the schema permits.
  • Diffable outputs: byte-identical re-renders mean version control works on deliverables; a changed SVG means changed input, full stop.
  • Traceability rendered: dossier sections resolve evidence ids back to their verbatim bodies, so the printed artifact carries its own audit trail.

Report-kind composition diagram — six dossiers from one input

The switch is exhaustive at the type level (const exhaustive: never) — an unknown report kind is a compile-time error in the package and a fail-closed error at the CLI, not a fallback to something approximate.

Where determinism comes from

  • @asd/render (suite/packages/render/src/): one compiler module per kind — journey-map.ts, service-blueprint.ts, kpi-tree.ts, … plus shared layout.ts, svg.ts, theme.ts, and a fallback.ts card grid for kinds without a bespoke compiler. Each is a pure function artifact JSON -> SVG string.
  • @asd/report (suite/packages/report/src/): fixed section composers over {project, artifacts, evidence, methods}; the only injected nondeterminism is the generatedAt timestamp, which sd_export_report accepts as an explicit --generatedAt flag for reproducible builds.
  • Filename stability: <kind>.<short-artifact-id>.svg and report.<kind>.html — re-exports overwrite in place, so your renders/ directory is always the current truth.

5. Critic Gate & Review Veto Rules (export edition)

[!IMPORTANT]

  1. Export is a downstream act: run sd_factcheck first and treat exit 1 as a hard stop — drafts with open vetoes do not belong in client-facing renders.
  2. The dossier resolves evidence ids to verbatim bodies; a citation that cannot resolve is an integrity failure, caught by factcheck, not by the renderer.
  3. Byte-identity on re-export is the standing audit: any diff means changed input (or a determinism bug — report it).
  4. generatedAt is the only sanctioned clock in the pipeline; pass it explicitly in reproducible/CI contexts.

6. Hands-On Lab Assignment

Objective

Prove determinism on your own project and inspect what the compilers actually emitted.

Steps

cd ~/Documents/github/agentic-service-designer
export ASD_WORKSPACE=/tmp/asd-lab-02-5
CLI="node suite/packages/runtime/lib/cli.mjs"
# (reuse your lab-02.4 project, or rebuild the spine from module 02.1's lab)
PID=<pid>; AID=<artifactId>

$CLI export-artifact --projectId $PID --artifactId $AID || exit 1
S1=$(md5 -q $ASD_WORKSPACE/$PID/renders/journey-map.*.svg)
$CLI export-artifact --projectId $PID --artifactId $AID >/dev/null || exit 1
S2=$(md5 -q $ASD_WORKSPACE/$PID/renders/journey-map.*.svg)
[ "$S1" = "$S2" ] || { echo "NONDETERMINISM"; exit 1; }

$CLI export-report --projectId $PID --kind artifact-dossier || exit 1
ls -l $ASD_WORKSPACE/$PID/renders/
# open the HTML: confirm the dossier prints each node's evidence quotes verbatim
grep -c "evidence" $ASD_WORKSPACE/$PID/renders/report.artifact-dossier.html
echo "LAB 02.5 PASS ($S1)"

Verification checklist

  • SVG re-export is byte-identical (same md5)
  • Report JSON receipt includes path, kind, generatedAt, bytes
  • The dossier HTML contains your evidence verbatims (resolved from ids)
  • export-report --kind nonsense fails closed (try it)
