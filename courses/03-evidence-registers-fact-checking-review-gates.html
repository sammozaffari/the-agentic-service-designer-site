Paradigm Shift 01 / 10

Evidence or It Didn't Happen

  • An insight without a citation is an opinion; an artifact without evidence is decoration.
  • Every downstream claim must resolve to a hash in the project evidence store.
  • The runtime enforces this at write time: dangling evidence ids are rejected, not discovered later.
  • Fact-checking is deterministic and CI-gated — no model judgment, only verifiable structure.
Any claim→Cited in evidence store?
YesClaim is auditable → may enter an artifact
NoClaim is rejected at write — fail closed
"In an agentic practice, the burden of proof is architectural."

Module 03.1 03 / 10

The Law of Artifacts: Why Chat-Based Agent Handoffs Cause Toxic Drift

  • Conversational handoffs drift: summaries summarize summaries until fidelity is gone.
  • Filesystem-first typed artifacts make every handoff explicit, diffable, and auditable.
  • Acceptance-unmet writes are retained as draft with a failures list — drift is visible, never silent.
  • The review-veto-log persists every rejection: institutional memory with teeth.
Agent handoff→Carried by?
Typed artifactSchema-checked, evidence-cited, replayable
Chat memoryUnverifiable, lossy, toxic drift across roles
"Chat handoffs summarize; artifacts preserve."
Module 03.2 04 / 10

Content-Addressed Evidence Registers: SHA-256 Cryptographic Provenance

  • sd_evidence_add computes id = SHA-256 over [source, kind, body, origin] — 64 hex chars, immutable.
  • The same evidence added twice yields the same id: the register deduplicates by construction.
  • sd_artifact_write rejects nodes citing ids not in the store: cites evidence <hash> which is not in the project evidence store.
  • Provenance is cryptographic, not procedural — it cannot be process-violated away.
Raw quote / row→ SHA-256 id→ evidence/index.json→ Cited by artifact nodes
"Provenance you cannot forge is provenance you can build on."

The Evidence Taxonomy: Quotes, Telemetry, and Document Registers

  • Exactly three evidence kinds: quote, telemetry, document — observation is rejected at the CLI.
  • Quotes carry voice-of-customer verbatim; telemetry carries operational ground truth; documents carry institutional constraint.
  • Methods declare evidence rules: journey-from-transcripts needs ≥3 records before it will even return its contract.
  • sd_evidence_query retrieves and sd_evidence_import bulk-ingests — same hash law.

Module 03.4 06 / 10

The Adversarial Critic Agent & The Review-Veto-Log Lifecycle

  • sd_review rows are typed: rowKind proposal|defect, severity critical|high|medium|low, optional rule, fix, evidenceId.
  • pass requires ≥1 evidence-cited row and zero defects → artifact status final.
  • veto requires ≥1 defect row and every defect must carry a fix → stays draft; the veto log is persisted.
  • The critic is a binding gate with a paper trail, not a vibe check.
Artifact draft→sd_review (critic)
PASS≥1 evidence-cited row · zero defects → status final
VETO≥1 defect row, each with fix → stays draft, veto logged, loop back
"A veto with a mandatory fix is quality assurance; a veto without one is just noise."
Module 03.5 07 / 10

Deterministic Fact-Checking in CI/CD with sd_factcheck & Quality Gates

  • sd_factcheck emits a per-artifact report: integrity (dangling), schema, acceptance, review verdict.
  • Exit 0 only when every artifact passes; exit 1 otherwise — CI gate semantics.
  • Wire it into CI: a hallucinated citation breaks the build exactly like a failing test.
  • No model judgment involved: the check is structural and replayable by anyone.
All project artifacts→sd_factcheck
exit 0Integrity + schema + acceptance + review all pass → merge allowed
exit 1Any failure → build breaks, failures listed per artifact
"If the build is green, every citation resolves — that is the whole promise."

Field Protocol 09 / 10

Fail-Closed by Design: Practicing the Negative Cases

  • Deliberate failure is a teaching tool: cite an invented hash and watch the write fail with the exact reason.
  • Run a method below its evidence minimum and read the fail-closed message: requires at least 3 evidence records.
  • Attempt phase-advance without a receipt JSON: refused, with the reason printed.
  • Every negative case exits non-zero — scripts assert on failure, not just success.
Hostile input→Runtime checks
ValidProceeds — with receipts
InvalidDangling ref · thin evidence · missing receipt → fail closed, exit 1
"A gate you have never seen refuse is a gate you do not understand."
