Course 10 — Installing and operating the platform

Operate, verify, publish

Installation is the beginning. Operating the platform means three standing habits: factcheck as a gate, drift checks before release, and receipts for every claim.

Factcheck as CI

sd_factcheck (or asd factcheck) exits nonzero while any design artifact is draft, failing integrity, or citing evidence that does not resolve — so it slots directly into CI:

- name: Engagement factcheck
  run: asd factcheck --projectId "$PROJECT_ID"

A green build means: every artifact final, every citation resolvable, every acceptance rule satisfied against the live manifest.

Drift checks and the release path

The source repository's own gates run the same philosophy at platform scale: secret scan, suite tests, compiler tests, pack drift (emitted packs must match a fresh emission byte-for-byte), article consistency, mermaid validity. The distribution repositories are regenerated — never hand-edited:

node scripts/publish-distribution-repos.mjs --root <parent-dir> --push

That script re-emits into a disposable directory, boots both vendored servers, runs claude plugin validate, commits with a provenance message, and pushes to both mirrors. Each repo carries provenance.json recording the source commit it was synced from — if that file is missing or stale, do not trust the copy.

Receipts for claims

Every capability claim in this platform binds to a receipt: live MCP boot transcripts, plugin-install inventories, session receipts with event ids. The pattern to copy for your own engagements:

Claim Receipt
server boots and serves initialize envelope + tool/resource/prompt counts
plugin installed claude plugin details inventory line
engagement state project store path + factcheck exit 0
phase decision approval receipt id, approver, timestamp, rationale
collaboration happened signed message events on the channel

When something breaks

Symptom First check
MCP tools missing in host absolute path in config; workspace trust (Kimi)
resources list tiny corpus roots overridden? bundled mcp/data/ intact?
CLI exits 1 on write read the named failure row; nothing was half-written
factcheck red dangling[] names the exact node + evidence id
packs look stale re-run emitter; drift check compares byte-for-byte

Capstone

You now have every surface: plugin, CLI, MCP server, role agents, method skills, distribution pipeline. Run one engagement across all of them — brief in chat, capture through MCP, synthesize via CLI, review through the critic, advance the human gate, render the export — and assemble the receipt set from the table above. That receipt bundle is the deliverable of this course.
