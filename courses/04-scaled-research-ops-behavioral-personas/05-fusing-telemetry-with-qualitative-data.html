🎯 Learning Objectives

  1. Theoretical Foundations: Ground data triangulation (Denzin) and mixed-methods service research — when quant corroborates qual, when it contradicts it, and what each outcome means.
  2. Agent Topology & Contracts: Show how kind: quote and kind: telemetry evidence coexist on one artifact node — the runtime's unit of fusion.
  3. Architecture & Schemas: Author triangulated nodes where the context/description fields carry the triangulation logic explicitly.

  5. Adversarial Verification: Verify that telemetry enters only through typed evidence records (no connectors, no streams) and that citations resolve identically for all kinds.
  6. Hands-on Practice: Add telemetry evidence to a project, cite it alongside quotes on a persona node, and pass the gate.

📖 1. Theoretical Grounding & Literature Synthesis

Triangulation as a service-design discipline

Denzin's triangulation principle — data, investigator, theory, method — exists because every single instrument is biased in a direction you cannot see from inside it. In service research the most productive axis is data triangulation across the qual/quant seam: interviews tell you what an experience meant; telemetry tells you what the population did; policy documents tell you what the service promised. Manning & Bodine (vol. 14, ch. 4) operationalize this as the closed-loop Voice of the Customer system: standing qualitative and quantitative collection reconciled continuously, not in an annual survey. Heskett et al.'s Service Profit Chain (vol. 20) is built on the same move — employee capability data, operational metrics, and customer outcomes are only meaningful when instrumented at the same unit level so they can corroborate or contradict.

Three outcomes of a triangulation attempt, each with a different design meaning:

  • Corroboration — the verbatim ("I waited forty minutes") and the metric (IVR mean hold 2380s ≈ 39.7 min) agree. Confidence rises; the claim can bear weight in a business case.
  • Complement — telemetry shows where (42% form abandonment at step 3), quotes explain why (the form loses uploads). Each fills the other's blind spot.
  • Contradiction — the dashboard says 87.4% SLA while tenants say "nothing happens". Contradiction is not a data error to be averaged away; it is the highest-value finding available, because it means the instrument and the experience measure different realities.

How fusion works in this toolchain — honestly

There is no fusion tool, streaming connector, or metrics pipeline in the runtime's 29 tools. Fusion happens at exactly one place: the artifact node's evidence[] array, which accepts content-addressed references to records of any kind. A telemetry snapshot enters the store as a typed record (asd evidence-add --kind telemetry --body '<json>' — a bounded, human-exported data excerpt), receives the same SHA-256 treatment as a quote, and is cited by the same {evidenceId, quote?} reference shape. The fusion is therefore:

  • Structural — one node cites both kinds; referential integrity applies identically (a dangling telemetry id fails the write exactly like a dangling quote id).
  • Explicit — the triangulation logic is written into the node's fields (context, description), so a reviewer can see why the quote and the metric are claimed to bear on the same behavior.

📊 4. Case Study Lens: Halcyon's Contradiction (Article 05)

Synthetic illustration — not a production log. Receipt ids above come from the verified live session.

Halcyon Logistics (fictional) is the contradiction case in pure form: SLA dashboards at 87.4% "acceptable" while shipper churn ran 11.8%. Neither instrument was lying — they measured different realities. The program's value came from refusing to average the two and instead instrumenting all five Service Profit Chain links at account-unit level, so quant and qual could be reconciled per account.

The module's fused nodes are the same discipline at citation granularity. When per-quiet-deserter cites "I do not report small issues any more" beside repair_form_abandon_rate: 0.42, the artifact is not claiming the quote caused the metric; it is recording that two instrument families independently observed exit behavior — and the critic row says so, citing the telemetry id. If the metric had instead shown 0.04 abandonment, the honest outcome would be a contradiction defect row, not a quieter quote.

# Negative: cite a telemetry id you never added → write refused, same as a dangling quote

Verification checklist

  • Telemetry entered as a bounded, typed record — no connector, no stream, no invented pipeline.
  • At least one node cites both quote and telemetry records; the telemetry ref omits quote.
  • fields.context (or description) states the corroboration/complement/contradiction logic explicitly.
  • A dangling telemetry id fails the write exactly as a dangling quote id does (kind-agnostic integrity).

🚀 Key Takeaways

  • ✅ Fusion is structural, not pipelined: one artifact node's evidence[] cites any kind; integrity checking is kind-agnostic and fail-closed.
  • ✅ The triangulation logic belongs in the fields — write the arithmetic and the claim ("2380s ≈ the forty-minute verbatim") where a reviewer can challenge it.
  • ✅ Contradiction between instruments is a finding, not noise. Record it as a defect row; never average it away.
  • ✅ Corroboration is citable: critic proposal rows can point at the telemetry evidenceId itself, making confidence auditable.
