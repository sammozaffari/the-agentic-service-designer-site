📖 1. Theoretical Grounding & Literature Synthesis

Why ingestion is a research-ops discipline, not a file dump

Design research generates fieldnotes, transcripts, photos, telemetry, and quotes faster than any team can hold in working memory. Martin & Hanington's Universal Methods of Design (vol. 18, ch. 2 and ch. 5) catalog the representational methods that convert that mass into shared cognitive models — but every one of them presupposes that the raw material was captured faithfully first. Stickdorn et al. (This Is Service Design Doing, vol. 01, ch. 4) make the operational version of the same point: research data only becomes "evidence" when it is collected under a declared intent, with consent, and in a form a second researcher can re-examine. When ingestion is sloppy, every downstream artifact inherits the sloppiness silently.

Three failure modes dominate unscaling qualitative intake:

  • Decontextualization — a quote is copied into a slide deck and loses its source, session, and ordinal position. Six weeks later nobody can tell whether "nobody ever came" was one tenant or forty.
  • Format decay — each investigator captures in a different shape (docx, spreadsheets, chat messages), so cross-source comparison requires manual re-transcription.
  • Provenance amnesia — claims survive while their origins rot. The deliverable outlives the evidence.

The agentic answer is not a bigger bucket. It is a typed, content-addressed store in which every record carries its own provenance, and in which every downstream artifact is mechanically forbidden from citing anything that is not in the store.

What "scaled ingestion" means in this toolchain — honestly

There is no ingest engine in @asd. There is no background watcher, no network fetcher, no transcription service. Scaled ingestion is exactly two operations, repeated:

  1. asd evidence-add — one typed record at a time (kind ∈ quote | telemetry | document), content-addressed by SHA-256 over (source, kind, body, origin).
  2. asd evidence-import — a deterministic batch operation over a workspace-local file or directory of transcripts, CSVs, or JSON, which parses each file loss-minimisingly and calls the same typed add per record.

Scale comes from repetition and determinism, not from a pipeline: 200 transcripts is 200 importable files walked in sorted order, each row hashed and stored with its origin. Because ids are content hashes, re-importing the same corpus is idempotent in content — the store deduplicates nothing silently, but identical (source, kind, body, origin) tuples always resolve to the same id, so provenance survives re-runs.

🤖 2. Agentic Topology & Role Contracts

Ingestion is not agent-free busywork: two method contracts bracket it, and both were retrieved live with asd method-run.

Role Where it appears Specific responsibility in this module Tools it calls
Researcher owner of discussion-guide-design (research phase) Designs the instrument that produces the transcripts: drafts open questions ordered rapport→sensitive, with probes for less experienced interviewers. sd_method_run (research-plan-design, discussion-guide-design), sd_artifact_write
Synthesizer downstream owner of synthesis methods Consumes what ingestion produces; cannot start until evidence thresholds are met (transcript-mining fails closed under 5 records). sd_method_run, sd_evidence_query
Critic reviewGate on every method here Rejects leading or double-barrelled questions on the guide; later rejects uncorroborated synthesis. sd_review
Human designer humanCheckpoints[].authority Confirms scope, consent, and intended decision (scope-confirmation, before-run) before any method executes. sd_phase_advance (with approval receipt)

Two verified fail-closed behaviors define the topology's edges:

$ asd method-run --projectId <pid> --methodId discussion-guide-design
asd method-run: method "discussion-guide-design" requires at least 1 artifact input of kind
research-plan; project has 0. Produce the typed input artifact before starting.

$ asd method-run --projectId <pid> --methodId transcript-mining
asd method-run: method "transcript-mining" requires at least 5 evidence records; project has 0.
Capture evidence with sd_evidence_add first.

The instrument precedes the transcript; the transcript precedes the mining. The runtime enforces the order, so the SOP cannot be silently skipped.

💻 3. Schemas & Verified Execution

The evidence record (@asd/core, store/evidence.ts)

export type EvidenceKind = 'quote' | 'telemetry' | 'document'   // "observation" is rejected

export type EvidenceOrigin = {
  readonly source: string          // human source label, retained on every record
  readonly path: string            // absolute file path the record came from
  readonly relativePath: string    // path relative to the import root
  readonly format: 'transcript' | 'csv' | 'json'
  readonly encoding: 'utf8'        // UTF-8 only; fatal decode otherwise
  readonly bytes: number
  readonly record: 'line' | 'row' | 'json-value'
  readonly ordinal: number         // 1-based position within its file
}

export type EvidenceRecord = {
  readonly id: string              // SHA-256 of JSON([source, kind, body, origin | null])
  readonly projectId: string
  readonly source: string
  readonly kind: EvidenceKind
  readonly body: string            // verbatim — CSV rows keep their quotes, lines are never re-serialised
  readonly capturedAt: string      // ISO 8601
  readonly origin?: EvidenceOrigin // present on imported records
}

The parser is deliberately loss-minimising: transcript lines and CSV rows retain their source text verbatim (including the CSV's own quoting), and JSON files become document records holding canonical values already present in the file. Nothing is inferred, summarized, or fetched.

📊 4. Case Study Lens: Northgate Health Telehealth Onboarding (Article 02)

Synthetic illustration — not a production log. Article 02 is a fictional composite; the receipt lines below come from the verified live session above, not from the article.

Northgate Health (fictional composite, ~40,000 members) ran 20 stakeholder interviews plus a 400-member survey to explain why only 45% of members finished telehealth enrollment. The article's research team turned that corpus into an evidence register before any journey mapping began — the same order this module teaches: instrument (discussion-guide-design), capture (typed adds + CSV import), then synthesis.

Two transferable patterns from the case:

  • Register before interpretation. Northgate's completion mystery only resolved (45%→76% after redesign) because every finding could be traced back to a specific interview or survey stratum. In the runtime, that traceability is not a discipline — it is enforced: transcript-mining declares evidenceRules: {traceability: "required", provenance: "required"} and any artifact node citing an unknown evidence id is rejected at write time.
  • Heterogeneous corpus, one store. Interviews (quotes), enrollment funnel numbers (telemetry), and insurer policy constraints (documents) coexisted in one register. The runtime mirrors this with the three-kind enum — and nothing else: asd evidence-add --kind observation fails closed with "arguments.kind" must be one of ["quote","telemetry","document"] (verified live, exit 1).

🔬 5. Hands-On Lab

Full instructions and the automated verifier live in courses/labs/lab-04-research-ops-personas/. Core exercise for this module:

export ASD_WORKSPACE=/tmp/asd-lab-04
CLI="node suite/packages/runtime/lib/cli.mjs"
mkdir -p $ASD_WORKSPACE/imports
printf '"I waited on hold for forty minutes before anyone picked up."\n"I gave up on the online form and emailed a photo instead."\n' \
  > $ASD_WORKSPACE/imports/int-01.csv

PID=$($CLI project-create --name "Lab04 Ingestion" --client "Fernwood Council" \
  --sector government --service "repairs reporting" | grep -o '"projectId": "[^"]*"' | cut -d'"' -f4)

$CLI evidence-import --projectId $PID --path $ASD_WORKSPACE/imports/int-01.csv --source int-01
# expect: 2 imported quote records, each with origin.record = "row" and ordinal 1..2

# Deliberate fail-closed demos:
$CLI evidence-add --projectId $PID --source t --kind observation --body "x"     # exit 1: invalid kind
$CLI evidence-import --projectId $PID --path https://example.com/x.csv --source t  # exit 1: URLs rejected

Verification checklist

  • Every imported record carries origin.relativePath, origin.record: "row", and origin.ordinal.
  • CSV quoting survives verbatim inside body (loss-minimising parse, no re-serialisation).
  • --kind observation is rejected with exit 1.
  • A URL or out-of-workspace --path is rejected before any file is read.
  • method-run transcript-mining fails closed until ≥5 evidence records exist.

🚀 Key Takeaways

  • ✅ Scaled ingestion = repeated typed adds + deterministic import, not an ingest engine. There is no watcher, fetcher, or transcription service; scale comes from content-addressed repetition over a workspace-local corpus.
  • ✅ Provenance is structural, not procedural. Every imported record carries its file, format, record type, and ordinal; downstream artifact nodes cannot cite anything outside the store.
  • ✅ The instrument precedes the transcript. discussion-guide-design fails closed without a research-plan, and transcript-mining fails closed under 5 records — the SOP order is enforced by the runtime.
  • ✅ The evidence kind enum is a gate, not a guideline: quote | telemetry | document, and everything else is refused.
