Course 09 — BUZZ for Agentic Service Design

Closing Discover: store artifacts and the human gate

The BUZZ channel coordinates; the ASD store is where the engagement actually lives. This module shows the store side of the same session — run with the standalone CLI pack (Course 10 covers installation).

Evidence first

Six records, content-addressed at capture time:

asd evidence-add --projectId northfield-follow-up-care-5e167990 \
  --kind quote --source patient-interview-01 \
  --body "Nobody called me after surgery; I googled whether my wound looked normal"

Each record returns a sha256 id — f76d01602b3dfc45… and five siblings. Those ids are the only currency later stages accept.

Method SOP with acceptance rules

asd method-run --projectId … --methodId aeiou-coding

The contract that comes back names the owner role (synthesizer), the corpus provenance, the output kind (affinity-cluster-set), and acceptance rules: minimum three nodes, minimum two evidence refs per node, non-empty theme field. These are not documentation — the write path enforces them.

The typed synthesis artifact

Three clusters, each citing two hashed records:

{"kind":"affinity-cluster-set","status":"draft","methodId":"aeiou-coding",
 "nodes":[
  {"id":"n1","label":"Post-op silence",
   "evidence":[{"evidenceId":"f76d01602b3dfc45…"},{"evidenceId":"8a97e877019c9695…"}],
   "fields":{"cluster":"communication","theme":"patients wait blind"}},
  {"id":"n2","label":"Repeated data entry", "…": "fragmentation"},
  {"id":"n3","label":"Confirmation chase", "…": "backstage-load"}]}

Critic pass promotes draft to final

asd review --projectId … --artifactId a202338b11c64b8b --verdict pass \
  --rows '[{"rowKind":"proposal","severity":"low","check":"clusters-grounded",
            "result":"pass","message":"All clusters cite captured evidence",
            "evidenceId":"f76d01602b3dfc45…"}]'

Rules worth memorizing: a pass requires at least one evidence-cited row and cannot carry defect rows; a veto requires defect rows each with a fix. A pass promotes draft → final only if acceptance still holds against the live manifest.

Factcheck, then the human receipt

asd factcheck --projectId …        # exit 1 while anything is draft/failing

asd phase-advance --projectId … --toPhase define --idempotencyKey nf-gate-1 \
  --approvalReceipt '{"receiptId":"nf-gate-discover-1","decision":"approve",
    "rationale":"Discover evidence and synthesis complete",
    "approvedBy":"mehran","approvedAt":"2026-08-23T08:30:00Z"}'

The gate re-verifies that every design artifact is final before moving discover → define. The receipt is stored in the project: named human, timestamped, reasoned. Runtimes cannot forge it because they cannot sign the gate flow — this is the authority boundary the BUZZ channel advertises in its kickoff.

Meanwhile, back on the channel, Kai's journey skeleton landed as its own store artifact with the id reported on-thread — coordination in BUZZ, persistence in the store, each proving what it is good at.

Hands-on lab

Run the full sequence on your engagement: six records → aeiou-coding → artifact → review pass → factcheck → gate. Deliberately submit one under- evidenced node set first and keep the rejection message; it is your best teaching artifact for what fail-closed means in practice.
