Agent role reference

The platform's team is ten role agents. Each role is a directory in the canonical tree — platform/agents/<role>/instructions.md — and every one opens with the same line: it inherits platform/_shared/role-contract.md in full and adds role specifics. No role may deviate from the contract; deviations are design changes, not local choices.

The contract fixes the collaboration protocol once, for all ten: handoffs are artifacts, not chat; every artifact write is replayable from the store; quotes are verbatim; acceptance rules are machine-checked on every write; the Critic sits on the write path; and phase boundaries end at the human designer, who approves, redirects, or kills.

The ten roles

Gate ownership

Gate ownership is data, not convention: every one of the 74 method manifests declares "reviewGate": "critic" (verified against the registry), and the engine enforces it. An artifact written through sd_artifact_write is persisted as draft no matter how clean its acceptance run is; only a Critic verdict recorded with sd_review makes it final-eligible. A veto demotes to draft with evidence-cited defect rows attached, and the verdict itself persists as a review-veto-log artifact — the Critic's own outputs are artifacts, so the review loop replays from the store like any other work product.

The Critic's instructions set the posture: run order is fixed (schema, then referential integrity, then acceptance rules, then judgment); verdicts name the rule violated; deny-listed placeholder values ("unknown", "tbd", "n/a") are automatic defects; most verdicts are medium severity — critical means fabricated evidence, broken gates, or a final artifact that fails fact-check. A veto without a fix suggestion is rejected at the tool boundary.

Only a human can overrule a veto, with written rationale in the gate decision.

Where the prompt text lives

The canonical prompt text for each role is platform/agents/<role>/instructions.md — for example platform/agents/critic/instructions.md holds the Critic's identity, ownership table, outputs, collaboration rules, method discipline, and quality bar. The shared protocol lives once in platform/_shared/role-contract.md.

The Claude Code pack carries the same text in the host's native format at platform/packs/claude-code/agents/<role>.md: a frontmatter block (name, description) prepended to the identical body. The pack file is a copy emitted by the compiler, not a fork — edit the canonical tree and regenerate, never the pack.

Served over MCP prompts

The MCP server exposes the ten roles as MCP prompts: prompts/list returns one prompt per role (the role name, the Agent: … heading as title, and the role's identity line as description), and prompts/get returns the shared role contract followed by the role's own instructions as a single user message — mirroring the "inherits in full" line, so the served prompt is never half the role. Real frame, trimmed:

NOTE
prompts/get critic:
  description="The adversarial conscience of the engagement. Sits on the write path, not after it:
  any artifact whose method manifest declares `reviewGate: critic` is final-eligible only after a
  Critic verdict. The Critic's job is to make every claim earn its place — evidence-cited,
  machine-checked first, judgment second. The Critic does not design; it defends the truth of the work."
  messages=1
  first 160 chars: "# SDAP Role Contract — the collaboration protocol\n\n> Canonical source:
  `docs/plans/2026-08-17-service-design-agent-platform.md` (§3.2, §3.5).\n> Every role agent […]"

The corpus roots (books/, articles/, platform/agents/) resolve from the nearest ancestor of the server module, or from the ASD_BOOKS_ROOT / ASD_ARTICLES_ROOT / ASD_AGENTS_ROOT environment variables; a server installed outside the repo serves empty lists rather than stale copies — the corpus is not shipped in the npm tarball.

Per-host packs re-emit the same roles

Eleven distribution packs — cli, mcp, claude-code, opencode, omp, dsh, grok, codex, agy, pi, kimi — are emitted from the canonical tree by platform/compiler/emit-packs.mjs, driven by platform/packs/manifest.json (10 agents, 75 skill sources, 74 skills shipped). The tree is never forked: agents/*, skills/*, and templates/* are copied into each host's native layout, and the whole pack set regenerates deterministically — emit-packs.test.mjs asserts byte-identical output.

What "native layout" means differs per host: Claude Code gets subagent files under agents/ plus the /asd command and skills; Kimi, Pi, and OMP get agents/ and skills/ directories; OpenCode gets an agent/ directory and opencode.json; Grok gets prompts/; Codex gets a project-conventions AGENTS.md; the mcp and cli packs ship the vendored server and the asd shim. Same ten roles, same contract, same skills — the host decides the packaging, never the content.

For the method skills these roles drive, see the skills reference; for the tools they call, the tool reference; for the MCP transport, the MCP server page.
