The Agentic Service Designer is a Service Design practice encoded as software. The canonical tree contains ten role instructions, 81 skill sources (80 skills ship), method and artifact contracts, seven authored templates, a 20-book corpus, and a runtime shared by the CLI, MCP server, coding-agent packs, BUZZ adapter, and DeepSeek Harness Studio. These pages describe the release that exists; they do not turn a pack layout into a claim of live host execution.

One canonical engine, many surfaces

The surfaces share the same tool registry and method contracts. A host pack changes how roles and skills are discovered; it does not change the acceptance rules. The common loop is:

  1. Capture evidence (quote, telemetry, or document).
  2. Select and inspect a method with sd_method_run.
  3. Write a typed artifact against that method's acceptance rules.
  4. Ask the Critic to pass or veto it with evidence-cited rows.
  5. Replay integrity, acceptance, and review with sd_factcheck.
  6. Stop at the human phase gate until a designer decides.

There are 39 catalog rows and seven authored templates. The catalog is a practice vocabulary, not a promise that every row has a live runtime schema; per-kind runtime typed schemas remain a Phase 2 boundary. The MCP resources and prompts are discovered from pack-local corpus roots, so a copied runtime without the corpus can still execute tools but returns empty resources/list and prompts/list results.

Read by goal

Practitioners — start with Getting started, then the tool reference, roles, and skills. The use cases show how evidence, artifacts, Critic review, and human gates compose in a synthetic engagement.

Tool-builders — read CLI, MCP, and ACP, then host packs. The source repository README explains how to emit a dedicated pack without copying generated files by hand.

DSH and BUZZ integrators — read DSH Studio and the BUZZ integration material in Use cases. Treat their live acceptance receipts as separate evidence boundaries; a generic MCP receipt does not prove a BUZZ mention or a DSH host interaction.

Documentation contract

Technical text is generated and checked like code. Run npm run test:scripts, npm run check:mermaid, and the appropriate pack/runtime tests before publishing. Counts, flags, installation snippets, and host claims must come from current source or a fresh isolated receipt. See docs/site/README.md for the authoring and link rules.
