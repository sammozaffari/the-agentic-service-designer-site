The Agentic Service Designer platform is the executable form of a service design practice: a ten-role agent team, a library of 74 method skills, a 38-kind artifact catalog and a 20-book knowledge base, all compiled from one canonical tree (platform/). These docs are the manual for running it. They describe what the engine actually does — every command transcript and count quoted here was captured from a real run, never written from imagination.

One engine, four delivery surfaces

Everything runs on the same engine — the suite/ packages (@asd/core, @asd/engine, @asd/knowledge, @asd/agents, @asd/runtime). What changes is the surface you drive it through:

Coding-agent plugin

Ten role agents as native Claude Code subagents, the method skills, the /asd orchestrator command and the engine vendored as an MCP server. The reference distribution.

Install it →

MCP server

The 16 engine tools plus the 215-resource knowledge corpus over stdio — Claude Desktop, Cursor, any MCP client. Self-contained bundle, nothing on PATH.

Wire a client →

CLI

The same engine as a standalone asd binary — scriptable, CI-friendly, no agent host required. The fastest way to see the gated-write loop work.

Run it →

DSH workbench

The suite loaded as a DeepSeek Harness plugin bundle — the flagship workbench with typed artifacts and renderers inside the harness app.

Load the profile →

Because the engine is shared, the core loop is identical on every surface: capture evidence, write an artifact against a method's acceptance rules, survive the critic review, land as final, and prove it with sd_factcheck. Getting started walks all four surfaces to the same first gated artifact, so you learn the loop once.

Each of the 38 catalog kinds pairs a fillable human template with a typed JSON schema; 32 kinds have the machine form live today, with deterministic renderers and machine-checkable acceptance rules behind them. The knowledge corpus — books, chapters and all 36 case-study articles — is exposed to tools as asd:// resources, cursor-paginated at 100 per page.

Reading paths

Practitioners — you run service design engagements and want the agent team doing the mechanical load. Start with Getting started on the Claude Code plugin, then Use cases for engagement-shaped walkthroughs, and the case-study archive for the same methods executed end to end — article 11 is the evidence-gated blueprinting flagship.

Tool-builders — you are wiring the engine into your own host or CI. Start with the CLI or MCP quickstart, then the references: engine tools, artifact catalog, skills library and agent roles.

Evaluators — you are assessing the practice. The Harness page is the two-minute version: the team, the method-as-code pattern, the knowledge library. Templates & plugins shows the artifact catalog. Then Use cases shows the governance loop — gated writes, critic vetoes, factcheck — running on real captured output.

Conventions in these docs

Command transcripts are quoted from real captures and trimmed with […] elisions only. Amber callouts flag real failure modes. Tables render as fact cards, matrices or before/after rows depending on their shape — that is the site's editorial system, not a mistake. If you are writing docs yourself, the contract lives in docs/site/README.md.
