The CLI

asd is the canonical runtime in a terminal. It uses the same 29 tool definitions as MCP and DSH, including the orchestration, canvas, template, and schema metadata tools. The parser is generated from each tool's JSON schema, so flag validation and the runtime cannot silently diverge.

Install the local-only pack

The emitted CLI pack contains a launcher and a bundled runtime. The launcher resolves only its own cli/bin/cli.mjs; it never falls back to a global asd, ambient executable, or sibling suite checkout.

TERMINAL
node platform/compiler/emit-packs.mjs --output /tmp/asd-packs
PACK=/tmp/asd-packs/cli
mkdir -p "$HOME/.local/bin"
ln -sf "$PACK/asd" "$HOME/.local/bin/asd"
export PATH="$HOME/.local/bin:$PATH"
asd --version
asd help

For a distribution checkout, the emitter requires Node 20+ and the suite's dependencies. A fresh release check runs the resulting launcher with isolated HOME, PATH, and ASD_WORKSPACE; a fake ambient executable must remain uninvoked. This is the supported bootstrap path.

Command names and flags

The canonical names are the 29 names listed below. Short names strip sd_ and replace underscores with hyphens: asd project-create is an alias for asd sd_project_create.

NOTE
asd <tool-name> [--flag value] [--flag=value] [--json '{"...": ...}']
asd help
asd --version

Values are coerced from the tool schema. Strings are passed as strings; numbers, booleans, arrays, and objects are validated before execution. Use JSON for an array or object. A boolean may be a bare flag or an explicit true/false. Unknown flags, missing required flags, positional arguments, and invalid enum values exit 1 with an actionable error.

Workspace and isolation

Projects are files on disk. The default root is ~/.asd/projects; set ASD_WORKSPACE for a project, test, or CI job. Never let a test use a designer's ambient workspace:

TERMINAL
export ASD_WORKSPACE="$(mktemp -d)/projects"
mkdir -p "$ASD_WORKSPACE"
asd project-create --name "Metrovale Access" --client "Fictional composite" \
  --sector public-transport --service "step-free journeys" --phase discover

The project contains project.json, evidence/index.json, artifact JSON files, rendered exports, and the sops/ directory. Those files are the record of truth; there is no hidden project database.

Evidence and artifact loop

Evidence kinds are closed: quote, telemetry, and document. For example:

TERMINAL
EVIDENCE=$(asd evidence-add --projectId "$PID" --source interview-01 \
  --kind quote --body "I cannot tell whether the lift is working." )

Evidence ids are content-addressed. sd_method_run returns a method's phase, role-attributed steps, output kind, input minimums, acceptance rules, and review gate. sd_artifact_write accepts a node array with evidence pointers. A failed acceptance check persists a draft and its failure rows; a dangling evidence id fails closed before writing.

TERMINAL
asd method-run --projectId "$PID" --methodId journey-from-transcripts
asd artifact-write --projectId "$PID" --methodId journey-from-transcripts \
  --title "Current-state journey" --nodes "$NODES"

All 74 methods currently declare a Critic review gate. Pass a review only with resolving evidence-cited proposal rows:

TERMINAL
asd review --projectId "$PID" --artifactId "$ARTIFACT" --verdict pass \
  --rows '[{"rowKind":"proposal","severity":"low","rule":"traceability","message":"Retain the source quote in the final artifact.","evidenceId":"'"$EVIDENCE_ID"'"}]'
asd factcheck --projectId "$PID"

An empty --rows '[]' pass is not valid. A veto requires at least one defect with a fix and leaves the candidate draft while writing a review-veto-log. sd_factcheck replays integrity, acceptance, and review for every artifact and exits 1 when its top-level pass is false, making it a CI gate.

JSON and scripting

For scripts, prefer the canonical sd_* names and capture ids from JSON output. Use --json when an entire object is easier to generate than individual flags:

TERMINAL
asd sd_project_create --json '{"name":"Metrovale Access","client":"Fictional composite","sector":"public-transport","service":"step-free journeys","phase":"discover"}'

The CLI prints either a human heading plus JSON or a JSON error. On failure it prints running \asd help` shows usageto stderr. Exit 1 means a usage/runtime error or a completed gate with a failing verdict; a successfulsd_artifact_writemay still returnaccepted: false` with a persisted draft, so inspect the payload rather than treating every exit-0 call as final.

Source and release checks

The canonical implementation is suite/packages/runtime/src/cli.ts; the pack launcher is emitted by platform/compiler/emit-packs.mjs. The release checks compile the suite, emit to a disposable root, boot the pack-local launcher from outside the checkout, and assert no ambient executable was invoked. Run:

TERMINAL
npm run test:scripts
npm run typecheck
node platform/compiler/emit-packs.release.test.mjs

The CLI is a runtime surface, not an agent host. It records orchestration plans and handoffs, but ACP remains record-only and it cannot spawn a role process by itself.

Format pin

Node 20 or newer; package version 0.1.0; emitted bundle built by the suite's compiler. See MCP for the same engine over stdio and host packs for coding-agent installation.
