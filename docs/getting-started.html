Getting started

Install the self-contained CLI, MCP server, Claude Code pack, or another host adapter and run one evidence-gated Service Design loop.

Every surface uses the same runtime contracts: capture evidence, inspect a method, write an artifact, pass the Critic gate, fact-check, and ask a human to advance the phase. Pick one surface below. The commands assume Node 20 or newer; host-specific execution is called out as verified, disposable, or unverified rather than inferred from file layout.

Emit a disposable pack set

The repository is the source of truth. Build the suite and emit into a scratch directory before copying a pack into a project:

TERMINAL
pnpm --dir suite install
node platform/compiler/compile.mjs
node platform/compiler/generate-skills.mjs
node platform/compiler/emit-packs.mjs --output /tmp/asd-packs

The output contains 12 targets. Do not hand-edit generated role or skill files; change platform/agents, platform/skills, or the emitter and regenerate.

CLI

Install the pack-local launcher. It invokes only its sibling cli/bin/cli.mjs; it does not search PATH, use a global asd, or require a sibling checkout:

TERMINAL
PACK=/tmp/asd-packs/cli
mkdir -p "$HOME/.local/bin"
ln -sf "$PACK/asd" "$HOME/.local/bin/asd"
export PATH="$HOME/.local/bin:$PATH"
export ASD_WORKSPACE="$(mktemp -d)/projects"
asd --version
asd help

The short command names are aliases for the canonical sd_* names:

TERMINAL
asd project-create --name "Metrovale Access" --client "Fictional composite" \
  --sector public-transport --service "step-free journeys" --phase discover
asd evidence-add --projectId <id> --source interview-01 --kind quote \
  --body "I cannot tell whether the lift is working before I travel."
asd method-list --phase research

Use --flag value, --flag=value, a bare boolean flag, or one complete --json '{...}' object. Arrays and objects are JSON values. See the CLI reference for the complete gate and scripting pattern.

MCP server

Start the server from the emitted pack, preferably with an absolute path in client configuration:

TERMINAL
node /tmp/asd-packs/mcp/mcp/bin/server.mjs

The standalone asd-mcp.json is a template. If the client starts processes from a different working directory, replace its relative argument with the absolute path to mcp/bin/server.mjs. The server speaks newline-delimited JSON-RPC 2.0, protocol revision 2025-06-18; tools/list returns 29 tools, resources/list returns 232 resources in pages of 100 when corpus roots are present, and prompts/list returns 10 roles. The MCP page has client-specific config and failure codes.

Claude Code plugin

The Claude Code pack is the native plugin surface:

TERMINAL
claude plugin marketplace add <repo>/platform/packs
claude plugin install asd@asd-platform

The plugin manifest, /asd command, ten subagents, 74 method skills, and plugin-root .mcp.json are emitted together. Claude expands ${CLAUDE_PLUGIN_ROOT} to the installed plugin directory, so the vendored server needs no PATH entry. Read the Claude Code guide before choosing manual copy; manual copy is a source-level fallback, not a second plugin implementation.

Other coding-agent packs

The host matrix and exact config shapes are in Host packs. The important boundary is that roles and skills are portable content while host execution is a separate acceptance claim:

  • OpenCode installs the emitted agent/ files into .opencode/agents/ and uses its mcp.asd local command array.
  • Codex uses AGENTS.md plus an MCP registration; it is not a native Codex plugin manifest.
  • Kimi uses .kimi-code/ and requires project trust for project-level MCP.
  • Grok is prompt-only and needs a separate MCP client.
  • AGY is a review-session contract; OMP and Pi are neutral trees pending host verification.

The first gated artifact

The shortest end-to-end loop is:

TERMINAL
asd evidence-add --projectId <id> --source interview-01 --kind quote \
  --body "I had to call three times."
asd method-run --projectId <id> --methodId journey-from-transcripts
asd artifact-write --projectId <id> --methodId journey-from-transcripts \
  --title "Current-state journey" --nodes '<evidence-cited JSON>'
asd review --projectId <id> --artifactId <artifact-id> --verdict pass \
  --rows '[{"rowKind":"proposal","severity":"low","rule":"traceability","message":"Keep the source quote visible in the final journey.","evidenceId":"<resolving-id>"}]'
asd factcheck --projectId <id>

A pass review must contain a resolvable evidence-cited proposal row. An empty --rows '[]' pass is intentionally rejected by the current review contract. Vetoes require a defect row with a fix; the candidate remains draft and a review-veto-log is persisted. A phase advance is a human decision, not an agent spawn.

ACP and integration limits

The shared ACP adapter is asd-acp/1 and currently supports record-only, fail-closed collaboration events. sd_orchestration_plan, dispatch, handoff, and phase tools record plans and outcomes; they do not imply that a CLI/MCP host can spawn a new agent. The BUZZ and DSH pages describe their own verified integration evidence. Do not use a generic pack boot receipt as proof of a BUZZ mention/reply or a DSH UI workflow.
