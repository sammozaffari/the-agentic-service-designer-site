The Claude Code plugin

platform/packs/claude-code is the reference coding-agent surface. It projects the canonical ten roles and 74 shipped method skills into Claude Code's native plugin shape, adds /asd, and wires the same self-contained MCP server through the plugin root. The pack is generated; edit platform/agents, platform/skills, or the emitter rather than an emitted agent file.

Install as a native plugin

The plugin is published as a standalone distribution repository. This is the fastest path and needs no source checkout:

TERMINAL
claude plugin marketplace add imehr/asd-plugin
claude plugin install asd@asd-platform

From a source checkout, the same plugin installs from the local packs tree:

TERMINAL
claude plugin marketplace add <repo>/platform/packs
claude plugin install asd@asd-platform

The distribution repository is regenerated from this monorepo by scripts/publish-distribution-repos.mjs; its provenance.json records the source commit it was synced from.

The marketplace manifest is platform/packs/.claude-plugin/marketplace.json; the plugin manifest is claude-code/.claude-plugin/plugin.json. Claude loads the plugin-root .mcp.json automatically:

DATA
{
  "mcpServers": {
    "asd": {
      "command": "node",
      "args": ["${CLAUDE_PLUGIN_ROOT}/mcp/bin/server.mjs"]
    }
  }
}

${CLAUDE_PLUGIN_ROOT} resolves inside the installed plugin. The vendored server therefore needs no global asd, PATH registration, npm install, or sibling suite checkout. A disposable pack boot receipt proves the bundled MCP server; a separate host acceptance test is required to claim a native Claude session executed it.

Manual project copy

Use this only when the plugin marketplace is unavailable. Keep the source paths explicit and do not overwrite an existing .mcp.json:

TERMINAL
PACK=/tmp/asd-packs/claude-code
TARGET=/path/to/project
mkdir -p "$TARGET/.claude" "$TARGET/mcp"
cp -R "$PACK/agents" "$TARGET/.claude/agents"
cp -R "$PACK/skills" "$TARGET/.claude/skills"
cp -R "$PACK/commands" "$TARGET/.claude/commands"
cp -R "$PACK/mcp/." "$TARGET/mcp/"
cp "$PACK/.mcp.json" "$TARGET/.mcp.json.asd"

For a project-root config, replace ${CLAUDE_PLUGIN_ROOT}/mcp/bin/server.mjs with ./mcp/bin/server.mjs in the copied config and merge it with the existing MCP servers. The manual copy is a project configuration, not a native plugin installation.

What ships

.claude-plugin/plugin.json plugin name, version, description, author
.mcp.json plugin-root MCP server wiring
agents/<role>.md ten role subagents with shared contract + role body
skills/<id>/SKILL.md 74 method SOPs after flagship substitution
commands/asd.md /asd orchestrator command
mcp/ self-contained runtime bundle, metadata, and corpus data
capabilities.json target-scoped supported/unsupported/unverified rows

The skill-source count is 75 because the authored service-blueprinting flagship and its generated twin are both sources; only 74 files ship after the flagship wins. The engine registry still has 74 executable method manifests, each with phase, role-attributed steps, acceptance rules, provenance, output kind, and Critic review gate.

How a role session works

/asd turns a brief into an orchestration plan, asks the role prompts to select methods, and routes tool calls through the vendored MCP server. A role is not a free-form persona:

  1. The Orchestrator scopes the project and phase.
  2. Researcher and Librarian establish evidence and provenance.
  3. Synthesizer, Mapper, Ideator, and Prototyper create method outputs.
  4. Measurer traces outcomes and tests.
  5. Critic validates the artifact and records pass/veto.
  6. Presenter assembles exports from final artifacts; Librarian checks provenance.
  7. The human decides the phase gate.

Every artifact node must cite a resolving evidence id. Acceptance failure stays as a draft with check.failures; a dangling pointer fails closed. A pass review must include an evidence-cited proposal row; a veto requires a defect and fix. sd_factcheck replays all three layers and exits 1 on any failure. The role prompt itself cannot bypass those runtime gates.

Current boundaries

The pack's MCP bundle advertises 29 tools, 226 resources, and 10 prompts when its corpus roots are available. Six emitted MCP bundles have fresh disposable stdio evidence; this Claude pack is one of them. That receipt does not prove native host execution in every Claude environment. ACP is asd-acp/1 record-only/fail-closed; a generic role dispatch cannot spawn a new process.

Regeneration and verification

TERMINAL
node platform/compiler/compile.mjs
node platform/compiler/generate-skills.mjs
node platform/compiler/emit-packs.mjs --output /tmp/asd-packs
node platform/compiler/emit-packs.release.test.mjs

Claude Code plugin layout is pinned to the current .claude-plugin/plugin.json, plugin-root .mcp.json, agents/, skills/, commands/, and vendored MCP shape. Re-run the host-specific acceptance receipt before asserting a new Claude Code version is supported. See tools, roles, and host packs.
