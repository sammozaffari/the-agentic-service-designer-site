Host packs and the compiler

platform/ is the source of truth. platform/compiler/compile.mjs builds the canonical inventory; generate-skills.mjs renders 74 executable method skills from 75 sources; emit-packs.mjs projects the same ten roles, metadata, and vendored runtime into twelve host targets. A pack is a distribution boundary, not a second implementation.

Emit and validate

TERMINAL
pnpm --dir suite install
node platform/compiler/compile.mjs
node platform/compiler/generate-skills.mjs
node platform/compiler/emit-packs.mjs --output /tmp/asd-packs

Use --output for a disposable emission. A release emission boots the emitted CLI and six MCP targets in isolated HOME/PATH/cwd/workspaces, then checks determinism and pack drift. The current receipt records 12 targets and fresh stdio evidence for buzz, claude-code, codex, kimi, mcp, and opencode: each reported 29 tools, 232 paginated resources, 10 prompts, a clean project → evidence → artifact → evidence-cited review → factcheck workflow, and no ambient executable invocation. This does not prove a native host UI loaded a pack.

TERMINAL
npm run test:scripts
node platform/compiler/emit-packs.release.test.mjs
node platform/compiler/check-packs-drift.test.mjs

There are 32 registered artifact-kind contracts, 38 catalog rows, and six authored templates. These contracts and catalog rows are not per-kind typed JSON schemas; that runtime schema surface remains a Phase 2 boundary.

Claude Code

The Claude pack is the reference native plugin. Install from the pack marketplace:

TERMINAL
claude plugin marketplace add <repo>/platform/packs
claude plugin install asd@asd-platform

It supplies ten role subagents, 74 skills, /asd, and a plugin-root .mcp.json that resolves ${CLAUDE_PLUGIN_ROOT}/mcp/bin/server.mjs. No global asd, PATH entry, or sibling suite checkout is needed. See Claude Code.

OpenCode

Copy the emitted project tree and merge its opencode.json with any existing config:

TERMINAL
mkdir -p .opencode/agents
cp -R /tmp/asd-packs/opencode/agent/. .opencode/agents/
cp -R /tmp/asd-packs/opencode/skills .opencode/skills
cp -R /tmp/asd-packs/opencode/mcp .opencode/mcp
cp /tmp/asd-packs/opencode/opencode.json ./opencode.json.asd

The current config shape is:

DATA
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "asd": {
      "type": "local",
      "command": ["node", "mcp/bin/server.mjs"]
    }
  }
}

Role files are .opencode/agents/<role>.md after the copy. Do not document legacy role names such as build or corpus-pipeline; the emitted roles are orchestrator, researcher, synthesizer, mapper, ideator, prototyper, measurer, critic, presenter, and librarian. Host execution remains unverified unless a current OpenCode acceptance receipt says otherwise.

Codex

Codex receives repository conventions plus an MCP server, not a native plugin:

TERMINAL
cp /tmp/asd-packs/codex/AGENTS.md ./AGENTS.md.asd
mkdir -p .asd-mcp
cp -R /tmp/asd-packs/codex/mcp/. .asd-mcp/
codex mcp add asd -- node "$PWD/.asd-mcp/bin/server.mjs"

If you prefer project TOML, merge the emitted block but change its argument to .asd-mcp/bin/server.mjs; never overwrite an existing Codex configuration. AGENTS.md carries evidence, provenance, Critic, and human-authority rules. The pack's MCP/repo contract does not claim Codex-native agent discovery or host execution.

Kimi

Project-level Kimi installation mirrors the pack and requires workspace trust:

TERMINAL
mkdir -p .kimi-code
cp -R /tmp/asd-packs/kimi/agents .kimi-code/agents
cp -R /tmp/asd-packs/kimi/skills .kimi-code/skills
cp -R /tmp/asd-packs/kimi/mcp .kimi-code/mcp
cp /tmp/asd-packs/kimi/mcp.json .kimi-code/mcp.json
cat /tmp/asd-packs/kimi/AGENTS.md >> AGENTS.md

The server command is node .kimi-code/mcp/bin/server.mjs. Trust the project when Kimi asks, and keep user-level config separate from project files. Kimi host execution is not inferred from the emitted mirror.

Prompt-only and neutral targets

Grok ships ten prompt files only; place the standalone MCP pack beside a client that can run it. AGY ships a critic review session and is not a native plugin. OMP and Pi ship neutral agents/ and skills/ trees with no executable runtime or MCP. Their current boundaries are intentionally honest: copy the source into the host's documented discovery locations only after verifying that host's format.

BUZZ and DSH

BUZZ's emitted target contains a persona projection and the shared MCP bundle. An authenticated BUZZ channel, human mention, relay delivery, runtime reply, canvas/index update, reload, and cleanup are separate live acceptance steps; a pack-local MCP boot receipt proves none of those on its own.

The DSH target is a Studio profile/capability adapter. DSH has its own UI slots, project state, artifact/review flow, provider-adapter canvas, and recovery receipts. Read DSH workbench for the live workflow and host-owned exceptions. Do not turn generic pack docs into DSH installation proof.

Regeneration rule

When a role or skill changes, edit the canonical source, run the compiler and emitter, review the generated diff, and rerun the release matrix. Never fix a generated pack by hand. The generated manifest.json and capabilities.json files are release data; their target, counts, and support reasons must remain in parity with the canonical inventory.
